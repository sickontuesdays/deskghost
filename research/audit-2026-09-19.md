# DeskGhost security + resource audit — 2026-09-19

Done before sharing v0.1 with the clan. Everything below was measured on the release build on a 2560×1440 +
1920×1080 two-monitor PC, driving the running app over its debugging port (`tools/cdp.js`, `tools/leak-test.js`,
`tools/measure.ps1`).

## What the app can and cannot do

| | |
|---|---|
| Runs as | the signed-in user, never elevated. Installs per-user (`%LOCALAPPDATA%\DeskGhost`), no admin prompt |
| Writes to | `%APPDATA%\com.sickontuesdays.deskghost` (catalog.json, overlay.json — 2.3 MB) and `%LOCALAPPDATA%\com.sickontuesdays.deskghost` (downloaded Bungie files + the WebView2 profile). Nothing else |
| Network | HTTPS to `www.bungie.net` only (verified live: the only outside connection was 104.17.100.21 = www.bungie.net) |
| Accounts | none. No Bungie login, no API key, no telemetry, no accounts, nothing uploaded |
| Registry | one per-user Run entry, and only if the user enables "Start with Windows". Removed on uninstall by `src-tauri/windows/hooks.nsh` |
| Other processes | never injected into, hooked, or read. The overlay is an ordinary topmost window |

## Findings and fixes

| # | Finding | Fix |
|---|---|---|
| 1 | The overlay sat on top of fullscreen games. A window over a fullscreen game stops Windows using its fast direct-to-display path, costing frame rate and adding input lag | Hide the overlay whenever a fullscreen window is present on its monitor; setting on by default. **Verified by screenshotting the real screen** |
| 1a | First attempt only checked the *foreground* window, so the Ghost popped back over a game whenever the game briefly lost focus (alt-tab, notification, background console) — seen live | Look for any fullscreen window on that monitor, not just the focused one. Skips our own windows, desktop/taskbar, minimised and DWM-cloaked windows, windows with title bars, and layered windows (other transparent overlays: Discord, GeForce) |
| 2 | Every shell applied to the desktop kept its decoded textures (several MB each) for the session | Only the shell on screen stays decoded (`showShell` in overlay.js) |
| 3 | Overlay window stayed up with the Ghost off, holding screen-sized compositor surfaces | Window is hidden while the Ghost is off, and its rendering is suspended |
| 4 | No Content Security Policy: pages could in principle load or contact anything | Locked to the app itself plus the local Bungie proxy. **Verified live**: outside `fetch` and outside `<script>` are blocked, the proxy still works |
| 5 | The local Bungie proxy accepted any path under `/common/destiny2_content/` | Strict character allowlist, no `..`, no `//`, no Windows device names (CON/NUL/COM1…). 13-case unit test (`cargo test`), and checked against all 19,615 real Bungie paths — none rejected. **Verified live**: non-content paths return 403 |
| 6 | Two setup runs at once would collide in one temp folder; a crash mid-setup left ~150 MB in `%TEMP%` | One run at a time; stale work folders cleaned at startup |
| 7 | Uninstalling with "Start with Windows" on would leave a startup entry for a deleted program | NSIS uninstall hook deletes it |

`cargo audit`: **0 known vulnerabilities** across 529 Rust dependencies. Seven warnings, all irrelevant: six
build-time-only crates marked unmaintained, and one (`glib`) that is Linux-only and not built on Windows.

## Memory: no leaks found

JS heap measured after a forced full garbage collection each time; process memory is every DeskGhost process.

| Stress test | Result |
|---|---|
| 24 different shells applied to the desktop Ghost | private RAM 259 → 252 MB (no growth); heap 7.2 → 8.3 MB |
| Ghost turned off and on 20 times | heap flat 8.4 → 8.3 MB; GPU objects returned to the same counts |
| 25 shells browsed in the picker preview | heap flat at 7.6 MB after the first few |
| Idle 10 minutes | heap flat at 7.4 MB; geometry/texture counts identical throughout |
| Picker window closed | 8 processes/395 MB → 7/274 MB, GPU 130 → 82 MB (fully released) |

## Resource use (release build)

| State | CPU | GPU | RAM (private) |
|---|---|---|---|
| Ghost on, defaults (30 fps, 108 px) | 7% of one core (0.3% of a 24-thread CPU) | 0.5% | ~285 MB |
| Ghost on, 60 fps / 200 px | 11% of one core (0.5%) | 0.8% | ~306 MB |
| Ghost off (overlay hidden) | 0.1% of one core | 0% | ~249 MB |
| Hidden behind a fullscreen game | ~0 | ~0 | unchanged |

Most of the RAM is the WebView2 engine itself (~250 MB), not the Ghost, which adds roughly 15–35 MB. GPU memory
(~80–130 MB) is held by WebView2 for as long as the app runs; only quitting releases it.

## Known limits (not defects)

- **Unsigned installer:** SmartScreen warns on first install, and some antivirus tools are wary of unsigned NSIS
  installers. Only code signing fixes this.
- **Disk use grows with what you pick:** each shell/shader is 1–2 MB, cached forever. All 580 shells would be
  several hundred MB. Settings → "Clear downloaded models" empties it; icons (~1,270) are kept.
- **A crash takes the Ghost with it** (release builds abort on panic). Nothing else on the system is affected;
  restart the app.
- **Not tested:** installing on a PC without WebView2 (the installer is set to fetch it), and the uninstall hook.
